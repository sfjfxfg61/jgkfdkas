# Проверки Victoria v4

Проверено 22.10.2026 в отдельной среде. Рабочий бот, аккаунты клиентов, Render и Supabase не использовались для этих проверок.

## Автоматические сценарии

34 теста: Python/pytest, обработчики с Telegram-заглушками, SQL на PostgreSQL в WASM (PGlite 0.5.11). Конкретные тесты лежат в `tests/`.

Проверено:

- Подпись счёта, привязка к Telegram ID, цена, срок, просроченность и лимит payload.
- Совместимость старых `simple1`, `simple2`, `simple3` с их исходными сроками.
- Новые тарифы и цены, подпись ручной цены и двухчасовой VIP-скидки.
- Восемь языков; нормализация `pt-BR`, `it_IT`, `UA`; отсутствие кнопок отключения уведомлений.
- Числовой ID блога превращается в ссылку с заявкой; кеш ссылки работает.
- Персональное сообщение использует `first_name`, экранирует HTML и не берёт username.
- VIP-уведомление содержит одну кнопку с правильной ценой.
- Pre-checkout отвечает до обращений к БД.
- Ручное предложение отправляет один подписанный счёт с выбранной ценой, доступ постороннему администратору запрещён.
- Неизвестный язык открывает выбор вместо молчаливого входа на EN.
- Inbox регистрирует пользователя один раз и передаёт данные обработчику.
- Повторяемость SQL-миграции и сохранение legacy-доступа без receipt.
- Один пользователь, сохранение первоначального источника и языка.
- Повторная оплата с тем же charge ID не создаёт второй платёж/срок/комиссию.
- Повторная отдельная покупка продлевает тот же тариф; покупка младшего тарифа не отнимает действующий VIP.
- Возврат идемпотентен, сохраняет другую покупку и не восстанавливает возвращённое при повторе payment update.
- Пожизненный канал остаётся после окончания отдельно купленного VIP.
- Партнёрская комиссия создаётся один раз, возвраты исключаются из заработанного без удаления истории.
- Один часовой follow-up независимо от повторных `/start`.
- Выдача lease одному worker, недоступность этой задачи другому до истечения lease, восстановление после срока.
- Дневные задания не дублируются; выключение уведомлений конфигурацией не выключает отзыв доступа.
- Архивация сохраняет переписку и агрегаты, не удаляет платежи.
- Ошибочный повтор charge с другим пользователем откатывается.
- RPC оплаты недоступна роли anon.
- VIP-заявка на звонок доступна нужному тарифу и не дублирует ожидающую заявку.
- Telegram offset не подтверждается, пока update не записан в БД.
- Подтвердить выполнение может только текущий владелец lease.
- Перед удалением клиента worker ещё раз проверяет продлённый доступ.

Также выполнены `python3 -m compileall -q .` и `ruff check . --select F`.

## Границы проверки

Не выполнялись реальные списания и возвраты Stars, отправки клиентам, звонки, deploy и изменение рабочей базы. Не воспроизводилась реальная многопроцессная нагрузка PostgreSQL/Supabase; проверены SQL-блокировки/claims и повторные обращения на отдельном экземпляре. Совместимость PostgREST, права бота, реальные каналы, региональные настройки Stars и сон Render проверяются при запуске по `DEPLOY_UPDATE.md`.

Схема fixture соответствует переданным колонкам, но не может подтвердить неуказанные production-триггеры, RLS-политики и изменения рабочей БД после выгрузки. Миграция выполняется транзакционно; перед рабочим применением сохраняется резервная копия.
