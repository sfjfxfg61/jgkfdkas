Victoria v3 — deploy checklist

1) Supabase SQL Editor: run HOTFIX_QUEUE_V3.sql ONCE.
   It does not delete users/payments. It adds crash-safe queue fields and atomic job claiming.

2) Render environment (no new variables required):
   AUTO_REPLY_AI=false
   FOLLOWUPS_ENABLED=true
   SUPABASE_KEY must be a server-side sb_secret_... key or legacy service_role JWT.
   Keep ADMIN_ID, BOT_TOKEN, SUPABASE_URL, PRIVATE_CHANNEL_URL and PUB_LINK_* as they are.

3) Deploy the new code.

4) In Telegram, as admin:
   /admin   -> visual admin panel
   /diag    -> FOLLOWUPS=true, DB queue/RPC=OK, Telegram bot=OK
   /jobs    -> queue status

5) Test from a second account:
   open paid options -> tap a payment plan -> do NOT pay.
   Expected checkout reminders: about 5 min, 30 min, 3 h, 12 h, 23 h, then every ~24 h.
   They stop when the user pays, blocks the bot, automation is paused, or the conversation is taken over manually.

6) Existing products/prices/recurring billing/payment access logic are unchanged.

Important: the recurring daily reminders are only for users who entered the sales funnel (opened an offer/checkout). The bot does not blindly spam every account in the database.
