# Обновление Victoria до v4

Рабочий Render и Supabase не изменялись. В архиве — подготовленный код и миграция для показанной схемы, не выгрузка твоих данных. Токен, ключ Supabase и значения ID со скриншота в проект не записывались.

## Порядок

1. Сохрани резервную копию Supabase и текущую версию приложения. Миграция создаёт таблицы и индексы, поэтому на большой базе её лучше выполнять в период малой нагрузки.
2. На время переключения останови старый экземпляр бота. Не запускай два polling-процесса с одним токеном.
3. В Supabase → SQL Editor выполни **весь** `migrations/001_victoria_v4.sql`. Это отдельная миграция, а не присланная схема `CREATE TABLE`. Она рассчитана на уже существующие таблицы пользователя.
4. Обнови файлы проекта в своём репозитории/Render. Рабочая директория должна содержать `Dockerfile`, `main.py`, `workers.py`, `storage.py` и остальные файлы этого архива.
5. Сохрани существующие переменные Render. Добавь `PUB_LINK_PT` / `PUB_LINK_IT`, если для них есть отдельные блоги. Иначе берётся EN. Все эти значения могут быть отрицательными числовыми ID каналов.
6. Убедись, что бот — администратор платного канала с правами приглашать и блокировать участников, а в блогах имеет право приглашать. Блог и платный канал должны быть разными каналами. Для заявок блог должен быть закрытым.
7. Сделай deploy. Бот проверяет версию SQL и права платного канала на старте. Ошибку не скрывает, если миграция не применена.
8. Пройди проверку ниже со вторым аккаунтом. Затем открой `/metrics` и `/stats`.

## Переменные

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | Текущий токен |
| `ADMIN_ID` | Твой Telegram ID |
| `SUPABASE_URL` | Текущий URL Supabase |
| `SUPABASE_SERVICE_ROLE_KEY` или `SUPABASE_KEY` | Серверный service_role / sb_secret ключ |
| `PRIVATE_CHANNEL_URL` или `PRIVATE_CHANNEL_ID` | Отрицательный ID **платного** канала; URL в этой старой переменной не ожидается |
| `PUB_LINK_UK/RU/EN/DE/FR/ES/PT/IT` | Отрицательный ID соответствующего **блога** |
| `FOLLOWUPS_ENABLED` | `true` |
| `REMINDER_TIME` | `20:00` или своё время `HH:MM` |
| `REMINDER_TIMEZONE` | `Europe/Kyiv` |
| `REMOVE_EXPIRED` | `true` |
| `VIP_DAYS`, `PERSONAL_DAYS` | Необязательно; по умолчанию `30` |
| `PRICE_MATRIX_JSON` | Необязательно; прежний формат `trial/forever/vip` сохранён |
| `PORT` | Прежний порт, по умолчанию `8080` |

`INVOICE_SIGNING_KEY`: если переменной раньше не было, **не задавай новый произвольный ключ при обновлении**. В этом случае подпись по-прежнему использует токен бота, чтобы старые выданные счета можно было проверить. Если ключ уже был — сохрани его. Подписанные счета привязаны к пользователю, цене, сроку и дедлайну; старые оплаченные неизвестные счета сохраняются в журнале для ручной сверки.

Для `PRICE_MATRIX_JSON` пример без секретов:

```json
{"ua":{"trial":100,"forever":250,"vip":500},"eu":{"trial":250,"forever":500,"vip":1000}}
```

Твои прежние `REMINDER_WINDOW_START/END` больше не управляют расписанием. Используется существующий `REMINDER_TIME`; накопившиеся отправки идут партиями после этого времени. Старые `automation_jobs`, не начинающиеся с `v4_`, эта версия не выполняет и массово не удаляет.

## Проверка после deploy

- `/start` с языком RU/UK и PT/IT: правильный язык, блог по заявке, «Пройти дальше» работает без вступления. Заявка в блог не одобряется ботом.
- Неизвестный `language_code`: появляется выбор из восьми языков.
- В тарифах три описания и три кнопки с корректными ценами, 🥺 у VIP. Нет продажи нового пожизненного доступа.
- Открой каждый счёт, проверь описание/Stars; сделай одну небольшую согласованную тестовую покупку. После подтверждения приходит доступ именно в платный канал; заявка туда одобряется.
- В `/user ID` видны язык, источник, история и покупка. `/metrics` показывает отсутствие failed.
- Из карточки отправь себе личное предложение: сначала предпросмотр, затем одно сообщение и одна кнопка оплаты.
- Через час после первого `/start` v4 приходит сообщение с Telegram `first_name`. На перезапущенном процессе задача остаётся в БД. Следующий `/start` не создаёт ещё одну часовую задачу.
- У бесплатного аккаунта ежедневное VIP-сообщение содержит одну кнопку; цена в счёте совпадает, через два часа старый промосчёт больше не подтверждается.
- После VIP доступна заявка на звонок; `/calls` показывает её владельцу. Переписка и звонки обслуживаются вручную.
- На тестовом коротком сроке проверь предупреждение об окончании, продление и удаление из платного канала. Для этих проверок используй отдельного тестового пользователя.
- Действующий старый пожизненный клиент не теряет канал после обновления и после окончания отдельно купленного VIP.

Локальные тесты не подтверждают реальные права бота в твоих каналах, фактическую доставку Telegram и успешность запуска на Render: эти пункты проверяются только здесь.

## Сбои и откат

`/metrics` показывает failed updates и jobs. Повтор — `/retry_update ID` или `/retry_job ID`. Удалять записи `payments` для повторной обработки нельзя: это финансовый журнал.

При ошибке миграции транзакция откатывается. При необходимости вернуть старый код можно остановить v4 и развернуть предыдущий образ: новые таблицы сохраняются, основные старые колонки остаются. Старый код не понимает новые тарифы и гранты, поэтому это временный технический откат; после первых продаж v4 обслуживание новых покупок лучше восстанавливать v4, а не пытаться управлять ими старой логикой.

Сроки рассылок предполагают работающий процесс. На Render free сервис может засыпать без входящих HTTP-запросов. Для устойчивой доставки нужна постоянно работающая конфигурация; один `/health` сам по себе не гарантирует отсутствие сна.
