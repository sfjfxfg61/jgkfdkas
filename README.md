# Victoria Bot v4

Обновлённый бот из переданного проекта: тарифы, Telegram Stars, два отдельных канала, переписка, рассылки, доступы и аналитика.

**Начни с `DEPLOY_UPDATE.md`. Сначала применяется SQL-миграция, затем обновляется код.**

## Тарифы

| Код | Название RU | Что включено | Новая покупка |
|---|---|---|---|
| `secret` | 💌 Наш секретик | Приватный канал | 30 дней |
| `mistress` | 👑 Моя повелительница | Приватный канал и личная переписка | 30 дней |
| `daddy` | 🥺 VIP-папочка | Приватный канал, личная переписка и заявки на звонки | 30 дней |

Для второго и третьего тарифа срок по умолчанию 30 дней, задаётся `PERSONAL_DAYS` / `VIP_DAYS`. Это принятое в реализации допущение: бессрочный личный сервис больше не продаётся. Уже приобретённый старый `forever` сохраняется, как и условия подписанных счетов `simple1/2/3`.

Описание находится над кнопками; кнопки содержат название и актуальную цену Stars. Цены сохранены: UA/CIS/LATAM/ASIA — 100/250/500; EU/US/GLOBAL — 250/500/1000. Ключи существующего `PRICE_MATRIX_JSON` остаются `trial/forever/vip` для совместимости конфигурации; они соответствуют новым `secret/mistress/daddy`.

## Сценарии

- `/start` → заявка в закрытый блог по языку → «Пройти дальше» без проверки членства → тарифы. Заявки в блог одобряет владелец вручную.
- Бот создаёт ссылки по числовым ID из `PUB_LINK_*`. Приватный платный канал — отдельный `PRIVATE_CHANNEL_URL` или `PRIVATE_CHANNEL_ID`; там заявки одобряются только при оплаченном действующем доступе.
- UA/UK → `uk`, RU, EN, DE, FR, ES, PT, IT. Нормализуются `pt-BR`, `it_IT` и подобные варианты. Неизвестный язык → выбор. Ручной выбор сохраняется. Для PT/IT без своего канала используется `PUB_LINK_EN`.
- Через час после первого `/start` в v4 — одно из четырёх сообщений с `first_name`. Повторные `/start` не создают новую цепочку. Очередь сохраняется при перезапуске.
- Ежедневные уведомления сохранены, по умолчанию с 20:00 Europe/Kyiv; отправка растягивается на время обработки очереди. Бесплатному пользователю приходит одно VIP-предложение с одной кнопкой. Скидка — половина текущей обычной цены, реальный срок два часа. Покупателям с действующим доступом — дружеское сообщение с меню. Публичных переключателей уведомлений нет; существующий `automation_paused` и блокировка бота учитываются.
- Оплата активирует доступ, повторная оплата того же тарифа продлевает его. Списание не рекуррентное. Продление и выдача доступа после оплаты выполняются автоматически. Сроки канала, переписки и звонков учитываются отдельно.
- Возврат отзывает гранты соответствующей покупки; другие приобретённые права сохраняются. Комиссия за возвращённую покупку исключается из доступного партнёрского заработка, финансовая история остаётся.
- Звонок — заявка и ручное согласование времени с владельцем. Одновременно одна ожидающая заявка. Бот не проводит звонки сам. Поддержка доступна всем, как прежде; платная личная переписка организована через существующий inbox, отдельная Telegram-группа не создаётся.

## Администрирование

`/admin` открывает кнопки и список команд.

| Команда | Назначение |
|---|---|
| `/stats`, `/funnel`, `/regions`, `/reminder_stats` | Серверный сводный отчёт, языки, источники, рынки, A/B |
| `/user ID` | Имя, язык, источник, регистрация, этапы, последние платежи и сообщения |
| `/pending` | Ожидающие ответа, имя и язык, первые 50 |
| `/messages ID` | История страницами по 20 записей; кнопка перехода к архиву |
| `/send ID текст` | Ручной ответ; закрывает только обращение, существовавшее до начала ответа |
| `/offer ID daddy 500 текст` | Подготовить предложение с выбранным тарифом и ценой; сначала предпросмотр |
| `/cancel` | Закрыть редактор предложения |
| `/calls`, `/call_done ID` | Заявки на звонки и отметка выполнения |
| `/payments` | Последние 20 платежей |
| `/partners` | Партнёры, привлечение и начисления с исключением возвратов |
| `/metrics` | Задержка очереди, ошибки, p95 запросов, размеры таблиц, соединения БД |
| `/repair` | Повторная сверка флагов доступа с грантами |
| `/retry_update ID`, `/retry_job ID` | Повторная обработка записи со статусом failed |

Также: `/user ID` → «Текст + кнопка оплаты» → свой текст → тариф → при необходимости другая цена → предпросмотр → отправка. Язык ручного текста выбирает администратор; бот автоматически локализует кнопку и описание счёта.

## Быстродействие и сохранность

- Одна регистрация пользователя на входящее сообщение; поля оплаты не перезаписываются.
- `PATCH` возвращает минимальный ответ; цены и переводы находятся в памяти.
- Серверные агрегаты и накопительные этапы воронки заменяют скачивание всех сообщений/событий. Отчёт кэшируется 30 секунд.
- Индексы на историю пользователя, наступившие задания и сроки прав; небольшие партии и атомарные SQL claims с lease.
- Оплата, грант, событие покупки и комиссия фиксируются одной транзакцией, повторная доставка определяется уникальным charge ID.
- Update сначала записывается в БД и только затем подтверждается смещением `getUpdates`. Необработанные updates остаются в очереди.
- На одного пользователя операции процесса сериализуются, при отзыве повторно проверяется действующий доступ.
- Сообщения старше 180 дней, события старше 90 дней и завершённые заявки старше 180 дней перемещаются в `*_archive`. После архивации сводные показатели сохраняются. Архивы в той же БД сами по себе не уменьшают общий объём хранения.
- Завершённые ежедневные задания удаляются через 30 дней, обработанные updates — через 7 дней. Старые ошибки ежедневных/expiry-рассылок архивируются после 90 дней, их технические архивы очищаются после 365 дней. Ошибки содержат только класс/код, без текста клиента и секретов; failed updates не удаляются автоматически.
- `users`, `payments`, партнёрские таблицы, возвраты и гранты не очищаются по возрасту.

Доставка Telegram-сообщений имеет семантику at-least-once: авария после приёма сообщения Telegram и до отметки в БД может привести к повтору сообщения. Финансовые эффекты при этом идемпотентны. Это ограничение не маскируется обещанием «ровно один раз».

## Проверки

Python 3.12. Runtime зависимости — `requirements.txt`; тестовые — `requirements-dev.txt`.

```bash
python3 -m pip install -r requirements.txt -r requirements-dev.txt
npm --prefix tests install
python3 -m pytest -q
python3 -m ruff check . --select F
```

SQL-тесты по умолчанию используют PostgreSQL в WASM через PGlite, без рабочей БД. Вместо этого можно задать `TEST_DATABASE_URL` **только на пустую одноразовую тестовую БД**: fixture создаёт таблицы и тестовые роли. Реальные Telegram-покупки и права бота проверяются отдельно после развёртывания по `DEPLOY_UPDATE.md`.

`AUDIT_AND_GROWTH.md` — разбор найденных проблем и план увеличения прибыли. `VALIDATION.md` — выполненные проверки и их границы.
